# PR-40 / US-28 — Recuperación de contraseña en Mobile

Sustituye «Contacta a soporte» por un flujo autónomo sobre los endpoints públicos existentes de IAM.
Desde «¿Olvidaste tu contraseña?» se solicita un enlace; el mensaje siempre es neutral.
En «Ya tengo un enlace» se pega el correo recibido, se elige y confirma la contraseña y se vuelve al login.
No requiere sesión, no refresca credenciales y no guarda el enlace ni la contraseña en almacenamiento local.
Los errores de red permiten reintentar; un enlace inválido/usado/vencido permite solicitar otro.

Reutiliza el tema Material de Rumbo, la API HTTP y el router del refactor integrado por el equipo.
Las nuevas clases mantienen domain → application → infrastructure/presentation y DI diferida.
No modifica Planning, Navigation, BLE, perfiles, versiones de dependencias ni el trabajo del mapper.

## Dependencia

La solicitud y confirmación usan `/api/v1/password-recovery/requests` (202) y
`/api/v1/password-recovery/confirmations` (204). El envío SMTP se completa en la rama API
`feature/communications-password-recovery-delivery`. Web ya procesa el enlace del correo; aquí se
pega manualmente. No se declara implementado un enlace profundo Android/iOS.
El proveedor de correo externo debe configurarse en el despliegue; las pruebas usan Mailpit local.

## Pruebas

`test/password_recovery_test.dart`: contrato REST sin token de sesión, validación, errores de red,
respuesta neutral, rechazo de enlaces, contraseñas coincidentes, doble envío bloqueado y acceso con
sesión expirada o sin sesión. Incluye pantalla de 320 × 640 con texto al 200 %.

Integración real, con API aislada y Mailpit ya iniciados:

```powershell
flutter test --no-pub test/live/password_recovery_live_test.dart --dart-define=RECOVERY_LIVE_API=true --dart-define=RECOVERY_API_URL=http://127.0.0.1:18080 --dart-define=RECOVERY_MAILPIT_URL=http://127.0.0.1:18025
```

El test crea una cuenta PATIENT, solicita por REST, lee el correo entregado por SMTP, confirma la
contraseña, rechaza el enlace ya usado y el login anterior y comprueba el login nuevo. No usa mocks.
Se omite por defecto para no depender de servicios externos en la suite unitaria.
